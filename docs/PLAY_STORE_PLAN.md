# RelateStats 上架 Google Play 規劃

> 撰寫日：2026-09-15（對應 v3.27）
> ⚠️ Play 政策會變。每一步送出前，以 Play Console 當下顯示的要求為準。

---

## 0. 先說結論：三個會卡住上架的問題

依目前程式碼（`AndroidManifest.xml`、`build.gradle.kts`、`accessibility_service_config.xml`）檢查，有三件事**不處理一定過不了審**：

| # | 問題 | 為什麼會被退 | 處理方式 |
|---|------|------------|---------|
| 1 | `applicationId = "com.example.relatestats"` | Play 不接受 `com.example` 開頭的套件名稱。**套件名稱上架後永遠不能改。** | 換成自己的，例如 `tw.<你的代號>.relatestats`。 |
| 2 | `READ_CALL_LOG`（匯入手機通話紀錄） | 通話紀錄是**受限權限**，只有預設電話／簡訊 App 或少數例外用途能用。社交統計不在例外清單。 | Play 版拿掉這個功能與權限（用 product flavor 保留一個自己側載用的完整版）。 |
| 3 | 無障礙服務用來量停留時間，而且會讀畫面內容（`canRetrieveWindowContent="true"`） | 不是給身障者用的 App 使用 Accessibility API，必須在 Play Console 填**無障礙 API 聲明**，附**操作影片**，並在 App 內做**明確揭露＋取得同意**。這是審核最常退件的項目，**即使全部照做仍有被拒的風險**。 | 見第 2 節「無障礙服務的三條路」。 |

另外兩件**必做但不難**：

- **明確揭露（Prominent Disclosure）**：通知存取會讀到訊息內容（常用詞統計），屬於「個人與敏感資料」。目前的引導頁只有一句話、還能「跳過」，**不符合規定**。要在「前往系統設定開權限」**之前**，跳出專門的揭露畫面，使用者按「同意」才繼續。
- **隱私權政策網址**：Play Console 必填，而且 App 內也要能點到。

好消息：

- Manifest **沒有 `INTERNET` 權限**，資料確實不會上傳。這讓「資料安全性」表單和隱私權政策都很好寫，也是審核時最有力的說明。
- `targetSdk = 36` 已符合目標 API 要求。
- 當機紀錄只寫在手機本地，不涉及第三方 SDK。

## 1. 需要你先決定的事

| 決定 | 選項 | 建議 |
|------|------|------|
| 套件名稱 | 任取，**上架後不能改** | `tw.<代號>.relatestats`，代號用你之後所有 App 都會沿用的名字 |
| 上架名稱 | 30 字元內 | 「RelateStats：社交時間統計」之類；**標題不要放 LINE、Instagram 等商標** |
| 開發者帳號類型 | 個人／機構 | 個人（機構要 D-U-N-S 編號，流程長很多） |
| 收費 | 免費／付費／內購 | 先免費。付費要另外設定收款資料，之後再加內購即可 |
| 停留時間功能 | 見第 2 節 | 建議走 B 路線 |
| 目標年齡 | 13+／18+ | **18+**，避開「兒童與家庭」政策的額外要求 |

⚠️ **換套件名稱等於是一個全新的 App。** 手機上現在這個版本的資料不會自動帶過去。
換之前先到「設定 → 備份」存成檔案，裝好 Play 版再匯入。上架前要實際測一次「舊版匯出 → 新版匯入」。

## 2. 無障礙服務的三條路

| 路線 | 做法 | 優點 | 缺點 |
|------|------|------|------|
| **A. 照原樣申請** | 保留無障礙服務，填聲明、錄影片、做揭露 | 功能完整 | 退件機率高；被拒後要重送，時程拉長數週 |
| **B. 分兩階段（建議）** | 第一版**先不含**無障礙服務，停留時間改用 `UsageStatsManager` 只算「每個 App 用了多久」（程式裡已經有 `UsageStatsManager` 的用法）；上架穩定後，再用更新版單獨送審無障礙功能 | 第一版幾乎沒有高風險項目，最快上線；就算無障礙被拒，App 本身已經在架上 | 第一版看不到「跟某個人聊天停留多久」，只看得到 App 層級 |
| **C. 永遠不上 Play** | 完整版只自己側載 | 零審核 | 無法給別人用 |

B 路線的技術做法：用 Gradle product flavor 分成 `play` 和 `full` 兩個版本。

```kotlin
flavorDimensions += "store"
productFlavors {
    create("play") { dimension = "store" }                  // 上架用：無 READ_CALL_LOG、無無障礙服務
    create("full") { dimension = "store"; applicationIdSuffix = ".full" }  // 自己側載用：全部功能
}
```

`READ_CALL_LOG` 和 `ChatTrackerService` 移到 `app/src/full/AndroidManifest.xml`，
UI 用 `BuildConfig.FLAVOR` 判斷要不要顯示「匯入通話紀錄」「停留時間偵測」。
兩個版本可以同時裝在同一支手機上（`.full` 後綴）。

## 3. 時程總覽

假設走 B 路線，從今天開始大約 **5～7 週**，其中 **2 週是強制的封閉測試**，無法縮短。

```
第 1 週     決策 ＋ 註冊開發者帳號（身分驗證要等幾天，先送）
第 1–2 週   程式合規改造（第 4 節）
第 2 週     發行建置、隱私權政策、商店素材
第 3 週     Play Console 表單 ＋ 內部測試
第 3–5 週   封閉測試：至少 12 人、連續 14 天
第 5–6 週   申請正式版存取權 → 送審（數天到一週以上）
第 6–7 週   分階段發布 20% → 50% → 100%
```

## 4. 階段一：程式合規改造

### 4.1 必做

- [ ] **換套件名稱**：`applicationId` 改掉。`namespace`（Kotlin 套件路徑）可以保留 `com.example.relatestats`，Play 只看 `applicationId`。
- [ ] **拆 flavor**：`play` 版移除 `READ_CALL_LOG` 與 `ChatTrackerService`（B 路線）。
- [ ] **明確揭露畫面**，在跳去系統設定開權限**之前**顯示，內容要包含：
  - 讀什麼：通知的寄件人名稱、App 名稱、時間；**訊息文字只拿來算詞頻，不保存原文**
  - 為什麼：統計你跟誰互動、聊了多少
  - 存在哪：**只在這支手機，App 沒有網路權限，無法上傳**
  - 按鈕：「同意並前往設定」／「不同意」。按不同意時 App 仍可開啟（顯示空狀態或範例資料）
- [ ] **引導頁的「跳過」不能略過揭露**：可以跳過介紹，但不能跳過同意。
- [ ] **設定頁加「隱私權政策」入口**，連到公開網址。
- [ ] **開啟 R8**：`isMinifyEnabled = true`、`isShrinkResources = true`，並用 release 版實機測一輪（Compose 通常不需要額外規則）。
- [ ] **簽署設定**：release 用 upload key 簽，金鑰資訊放 `keystore.properties`，**加入 `.gitignore`，絕不能 push 到 GitHub**。
- [ ] **匯入備份相容性**：確認新套件名稱的 App 能讀舊版匯出的備份檔。

### 4.2 建議做（提高過審率）

- [ ] **範例資料模式**：審核人員的手機上沒有你的聊天紀錄，打開是空的會很難審。引導頁已有 `DemoDashboardScreen`，確保不開任何權限也看得到完整範例。
- [ ] **拿掉顯示「Debug」「診斷」字樣的殘留程式**（已移除的偵測診斷對話框程式碼可一併刪除）。
- [ ] **App 圖示**：確認 adaptive icon 在圓形、方形遮罩下都正常。
- [ ] **使用說明**：`USER_GUIDE`／`USER_FAQ` 移除 Play 版沒有的功能（匯入通話紀錄、無障礙停留偵測），或依 flavor 顯示不同內容。

## 5. 階段二：發行建置

1. **產生 upload key**（Android Studio → Build → Generate Signed App Bundle → Create new）
   - 金鑰檔與密碼存兩份：電腦＋雲端密碼管理器。**遺失 upload key 可以向 Google 申請重設，但要等好幾天**
2. **啟用 Play App Signing**（建立 App 時預設就是）：真正的簽署金鑰由 Google 保管
3. **建置 AAB**：`.\gradlew.bat bundlePlayRelease`（Play 只收 `.aab`，不收 `.apk`）
4. **版本號**：`versionCode` 每次上傳都要比上次大，沿用目前的遞增規則即可
5. **release 版實機測試**：用 `bundletool` 或內部測試軌裝到手機上測，不要只測 debug 版

## 6. 階段三：帳號與商店素材

### 6.1 開發者帳號

- 到 Play Console 註冊，一次性費用 **US$25**
- 個人帳號要**身分驗證**（證件＋地址），審核要幾天，**第一週就先送**
- 需要一支 Android 手機完成裝置驗證
- 聯絡 email 會公開在商店頁，建議另開一個專用信箱

### 6.2 隱私權政策

必須是**公開、不需登入、非 PDF** 的網頁。免費做法：

- GitHub Pages（若目前 repo 是私人的，另開一個公開 repo 只放這一頁）
- 或 Google 協作平台

內容大綱：

1. App 讀取哪些資料：通知（寄件人、App、時間、訊息文字的詞頻）、App 使用時間
2. 用途：只用於在手機上顯示你的互動統計
3. 儲存：只存在手機本地；App 沒有網路權限，不會傳送到任何伺服器，開發者也看不到
4. 備份：Android 系統自動備份（若手機有登入 Google 帳號）與使用者自行匯出的檔案
5. 分享：不分享給任何第三方，沒有廣告、沒有分析 SDK
6. 刪除：App 內「清除資料」或解除安裝即刪除
7. 聯絡方式、生效日期

### 6.3 商店頁素材

| 項目 | 規格 | 備註 |
|------|------|------|
| App 名稱 | ≤ 30 字元 | 不放第三方商標 |
| 簡短說明 | ≤ 80 字元 | 例：「看見你把時間花在誰身上。資料只存在手機，不上傳。」 |
| 完整說明 | ≤ 4000 字元 | 功能列表＋隱私說明。提到 LINE、Instagram 時只能描述支援，不能暗示官方合作 |
| 圖示 | 512×512 PNG | 32 位元，含 alpha |
| 主題圖片 | 1024×500 JPG／PNG | 商店頁頂端橫幅 |
| 手機截圖 | 至少 2 張，建議 4～8 張 | **一律用範例資料截圖，不能出現真實聯絡人名字**；也不要出現 LINE／IG 的 logo |
| 分類 | 「生活風格」或「社交」 | |
| 語言 | 繁體中文（台灣）為預設 | 之後可加英文 |

截圖建議順序：概況 → 排行 → 今日互動報告 → 分析（幾點在聊）→ 聯絡人標籤 → 配色選擇 → 隱私說明畫面。

## 7. 階段四：Play Console 表單（應用程式內容）

| 表單 | 怎麼填 |
|------|--------|
| 隱私權政策 | 填 6.2 的網址 |
| 應用程式存取權 | 「部分功能受限」→ 說明：不需帳號；需開啟通知存取才會有資料；不開權限可在引導頁點「觀看排版範例」看完整範例 |
| 廣告 | 否 |
| 內容分級 | 填 IARC 問卷：無暴力、無賭博、無使用者互動（App 內沒有聊天或分享社群功能） |
| 目標對象 | 18 歲以上 |
| 資料安全性 | 見 7.1 |
| 新聞應用程式／政府／金融／健康 | 皆為否 |
| 無障礙 API 聲明 | B 路線第一版：不需要（`play` 版沒有無障礙服務）|
| 敏感權限聲明 | `play` 版沒有 `READ_CALL_LOG`，不需要 |

### 7.1 資料安全性表單

App 沒有 `INTERNET` 權限，資料不會離開手機，因此：

- 「是否收集或分享使用者資料」：**否**（只在裝置上處理、不傳出裝置的資料，不算「收集」）
- ⚠️ **送出前再確認一件事**：Android 系統自動備份（`allowBackup="true"`）會把資料送到使用者自己的 Google 雲端。依 Google 說明，這類由系統處理的備份通常不需申報，但請以填表當下 Play Console 的說明文字為準。若不確定，可以把 `allowBackup` 設成 `false`，只保留「匯出檔案」，表單就完全沒有模糊空間。

## 8. 階段五：測試軌

### 8.1 內部測試（第 3 週）

- 最多 100 人、幾乎不用審核、上傳後幾分鐘就能裝
- 先自己用 Play 下載的版本完整跑一輪：引導頁 → 揭露 → 開權限 → 收到通知 → 回顧 → 備份匯入

### 8.2 封閉測試（強制，第 3–5 週）

⚠️ **2023 年 11 月之後註冊的個人帳號**，必須先完成：

- 封閉測試**至少 12 位**測試人員
- 這些人**連續 14 天**保持加入測試
- 之後才能在 Play Console 申請「正式版存取權」

實務做法：

- 找 15～20 人（預留會中途退出的），用 Google 群組管理名單最方便
- 測試人員要用 **Android 手機**，並用加入名單的那個 Google 帳號從 Play 安裝
- 請他們**真的每天開幾次**，申請正式版時 Google 會問測試期間的參與狀況與收到的回饋
- 期間至少發一個修正版，展現有在根據回饋改進

### 8.3 申請正式版存取權

Play Console 會問：

- 怎麼招募測試人員
- 測試人員的使用情況與回饋
- 根據回饋做了哪些修改
- App 準備好上架的理由

把封閉測試期間的修改整理在 `docs/CHANGELOG.md`，填表時直接引用。

## 9. 階段六：正式發布

1. 建立正式版，上傳 AAB，填版本說明（繁中）
2. 選擇國家／地區：先只選**台灣**，之後再擴大
3. 送審：通常數天，首次送審或含敏感權限可能超過一週
4. **分階段發布**：20% → 觀察 2～3 天當機率 → 50% → 100%
5. 被退件時：Play Console 與 email 會寫明違反哪條政策。照著改完重送，**不要直接在評論區或信件裡爭論**；確實有誤判時使用 Console 內的申訴表單

## 10. 上架後

- **Android Vitals**：當機率 > 1.09%、ANR > 0.47% 會影響曝光。每次更新後看一次
- **回覆評論**：尤其是「權限太多」「不敢開」類的，說明資料不上傳
- **每年目標 API 更新**：Google 每年 8 月底左右要求提高 `targetSdk`，沒跟上的話新使用者會看不到 App
- **政策信件**：開發者帳號信箱收到的政策通知要看，通常有 30 天修正期
- **第二階段（B 路線）**：第一版穩定後，另開一個更新版送審無障礙服務（聲明＋影片＋揭露）。被拒也不影響已上架的版本
- **開發者帳號維持活躍**：長期沒有更新或登入，帳號可能被標記為不活躍

## 11. 風險清單

| 風險 | 機率 | 影響 | 對策 |
|------|------|------|------|
| 無障礙服務被拒 | 高 | 停留時間功能無法上 Play | B 路線：第一版不含，之後單獨送審 |
| 揭露不足被退件 | 中 | 退件重送 | 照 4.1 做專門的揭露畫面，不可跳過 |
| 審核人員看不到內容 | 中 | 以「功能不完整」退件 | 範例資料模式＋在「應用程式存取權」寫清楚 |
| 封閉測試人數不足 14 天 | 中 | 延後上架 | 多找幾人；期間提醒大家不要退出 |
| 商標問題（LINE、IG） | 低～中 | 商店頁被要求修改 | 標題、圖示、截圖不放第三方名稱與 logo |
| upload key 遺失 | 低 | 數天無法更新 | 雙重備份 |
| 換套件名稱後自己的資料遺失 | 中 | 累積紀錄消失 | 換之前先匯出，實測匯入 |
| 通知格式因 App 更新改變 | 持續 | 統計抓不到 | 上架後持續維護；使用說明寫明限制 |
