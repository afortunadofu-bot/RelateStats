## 這個 repo 只需要記住的幾條

### 品牌 ≠ App 名稱

| | |
|---|---|
| 品牌 | **小數據所**（tagline：日子有數） |
| 這個產品 | **RelateStats**（規範寫的一句話：時間到底給了誰） |
| 另外兩個產品 | 壽星日、Bandary |

規範明文：**tagline 與 positioning statement 是兩個不同的東西，不要混用。**
程式裡對應的是 `BRAND_HOUSE_TAGLINE`（日子有數）與 `PRODUCT_TAGLINE`（看見你把時間花在誰身上），
兩個常數不要互換、不要合併成一句。

### 品牌只出現在三個地方

1. **署名層**：App 設定頁頁尾、about 頁
2. **開發者層**：Play 開發者名稱與開發者頁面
3. **對外帳號層**：Threads、GitHub

⚠️ **不要動 App 的視覺資產**：icon 不改、商店主題圖片不改、
**不要把品牌色（amber `#F2A73B`）套進 App 介面**。
RelateStats 的莫蘭迪配色與深色模式不需要為品牌讓步。

### App 內的署名長什麼樣

設定頁捲到最下面（`SettingsView` 頁尾）：

```
      [RelateStats 的記號]
        RelateStats
   看見你把時間花在誰身上          ← PRODUCT_TAGLINE
    RelateStats v<版本>           ← 版本號旁一定要有 App 名稱

   ┌──────────────────────┐
   │      開發與著作權        │
   │   小數據所｜Celine Fu    │   ← BRAND_AUTHOR
   │       聯絡信箱          │
   │  celine.fu.work@gmail  │   ← FEEDBACK_EMAIL
   └──────────────────────┘

      小數據所 · 日子有數          ← BRAND_SIGNATURE（標準署名）
        © <年> 小數據所
```

⚠️ 版本號旁邊一定要寫 App 名稱（`RelateStats v1.0.0`，不是只寫 `v1.0.0`）。
使用者回報問題時截的就是這一行，沒有名稱就看不出是哪個 App。

### 改信箱時要同時改四處

`FEEDBACK_EMAIL`、`docs/play/SUBMISSION.md`（開發人員聯絡資訊）、
`docs/privacy-policy.html`、Play Console 的開發者聯絡資訊。
