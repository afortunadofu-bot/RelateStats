# 功能許願板：建立步驟

App 裡的「設定 → 功能許願區」已經做好了。目前只有「寄出」那條路（開使用者自己的郵件 App）。
**要讓使用者互相看到願望、互相投票，需要一個外部網頁**——照下面做，大約十分鐘。

---

## 為什麼是外部網頁，不是做在 App 裡

⚠️ **App 沒有 `INTERNET` 權限，也不會為了許願區加上去。**

「App 沒有網路權限、資料無法離開這支手機」這句話同時寫在：

- `docs/privacy-policy.html`
- Play Console 的資料安全性（Data safety）申報
- 無障礙 API 聲明
- 商店的簡短說明與完整說明
- App 內的權限揭露對話框

加上 `INTERNET` 等於這五個地方全部要重寫、重新申報，而且 Play 對「使用者自建內容」
另有要求（檢舉機制、封鎖機制、內容審核），沒做會被拒。

許願板是一個**一般網頁**，App 只是丟一個 `ACTION_VIEW` 給瀏覽器，
就跟「隱私權政策」那個入口一樣。App 本身完全不連線。

---

## 第 1 步：建立 Google 表單（收願望）

1. 到 https://forms.google.com ，用 `celine.fu.work@gmail.com` 登入，建立空白表單。
2. 表單標題：`RelateStats 功能許願`
3. 表單說明貼這段：

```
想要 RelateStats 多什麼功能？寫下來，大家一起投票。
愈具體愈好：在哪一頁、想看到什麼。
送出後會出現在許願板上，其他人可以投票給你也想要的功能。
這份表單不會蒐集任何個人資料，也不要填入你的聯絡人姓名。
```

4. 題目：

| # | 題型 | 標題 | 設定 |
|---|------|------|------|
| 1 | 段落 | 你希望多什麼功能？ | 必填 |
| 2 | 單選 | 這是哪一類？ | 選項：新功能／現有功能改進／畫面與操作／其他。必填 |
| 3 | 簡答 | 想被回覆的話留個暱稱（可不填） | 非必填 |

⚠️ **不要**開「收集電子郵件地址」，也不要加任何要求真實姓名的題目。
表單說明已經寫了不要填聯絡人姓名——這點很重要，使用者很容易順手把朋友名字打進去。

5. 設定 →「回覆」→ 確認**沒有**勾「限制為同機構使用者」，任何人都能填。
6. 右上角「傳送」→ 連結圖示 → 勾「縮短網址」→ 複製。
   **這是 `WISHLIST_FORM_URL`。**

---

## 第 2 步：建立公開結果頁（看願望＋投票）

Google 表單本身沒有「按讚」，所以用試算表做公開的許願板。

1. 表單的「回覆」分頁 →「連結至試算表」→ 建立新試算表。
2. 在試算表裡新增一個分頁，命名為 `許願板（公開）`。

3. **先加一個審核欄**。到許願那張回應分頁（目前是 `Form Responses 2`，
   欄位是 A 時間、B 你希望多什麼功能、C 這是哪一類、D 暱稱），
   在 **E1** 打上 `公開`，E 欄用「插入 → 核取方塊」。

   ⚠️ 預設不打勾＝不公開。使用者可能把朋友的真名、電話打進願望裡，
   **公開的那份一定要是「你看過才放上去」**，不能是表單一送出就直接上牆。
   新進來的那一列如果沒有自動出現核取方塊，直接打 `TRUE` 也可以。

4. 在 `許願板（公開）` 的 A1:C1 打上標題 `願望`、`分類`、`暱稱`，A2 貼上：

```
=IFERROR(
  FILTER({'Form Responses 2'!B2:B, 'Form Responses 2'!C2:C, 'Form Responses 2'!D2:D},
         'Form Responses 2'!E2:E=TRUE),
  "還沒有公開的願望")
```

   分頁名稱如果不一樣，把 `Form Responses 2` 換成你實際那張的名字。
   ⚠️ 這裡刻意**不帶時間戳記**：時間＋暱稱組合起來比單獨一項更容易認出是誰。

4. 加一欄「👍」給大家投票：因為試算表的公開連結只能給「檢視」權限，
   投票要另外做。兩種做法挑一種：

   - **簡單版**：許願板上每則願望附一個「我也要」的表單連結（第二份 Google 表單，
     題目是單選「你想投給哪一則？」，選項就是目前的願望）。每週手動更新選項。
   - **省事版**：在試算表裡用 `COUNTIF` 統計第二份表單的投票數，自動更新票數欄。

5. **用「發布到網路」，不要用「共用」。**

   檔案 → 共用 → **發布到網路** → 左邊的下拉選單選 **`許願板（公開）` 這一張工作表**
   （不要選「整份文件」）→ 發布 → 複製網址。
   網址長這樣：`https://docs.google.com/spreadsheets/d/e/.../pubhtml?gid=...&single=true`

   **這是 `WISHLIST_BOARD_URL`。**

⚠️ **這份試算表同時放了封測報名與許願三份表單的回應，所以絕對不能用
   「共用 → 知道連結的任何人」。** 那是**整份文件**層級的權限，
   會把每一個分頁都打開，包括封測報名那兩份（裡面有暱稱、可能有聯絡方式）。
   「發布到網路」可以只發布指定的一張工作表，其他分頁完全不受影響——
   這是兩件不同的事，不要混用。

⚠️ 就算只發布一張，**也不要直接發布 `Form Responses N`**。
   表單之後多加一題，那一欄會自動出現在公開頁上，你不會收到任何提醒。
   公開的永遠是你自己用公式組出來的 `許願板（公開）`。

## 第 3 步：把網址填進 App

`MainActivity.kt` 裡：

```kotlin
const val WISHLIST_FORM_URL = ""     // ← 第 1 步的表單連結
const val WISHLIST_BOARD_URL = ""    // ← 第 2 步的試算表檢視連結
```

兩個都空著的時候，許願區只顯示「寄出」那條路，不會出現點了沒反應的按鈕。
填好任一個，對應的按鈕就會自動出現。

## 要注意的事

- **公開的願望要先看過再放上去**。使用者可能不小心把朋友的真名、電話打進願望裡。
  試算表的 `許願板` 分頁是你手動整理的那一份，不是原始回應——這層隔離要保留。
- **不要把原始回應試算表設成公開**。那裡面可能有暱稱欄與時間戳記。
- **「共用」和「發布到網路」是兩件事**。共用是整份文件（所有分頁一起開），
  發布到網路可以只發布一張工作表。這份試算表裡還有封測報名的回應，
  所以只能用後者，而且只選 `許願板（公開）`。
- **發布之後要自己驗一次**：用無痕視窗開那個網址，確認只看得到願望那一張，
  而且沒有暱稱以外的個資。無痕視窗很重要——你自己的瀏覽器有登入，
  看得到的東西跟陌生人看到的不一樣。
- Play 的使用者自建內容政策：這個許願板在 App 之外，不受管轄。
  但如果哪天決定把願望搬進 App 內顯示，那就會受管轄，需要檢舉與封鎖機制。
- 許願板換網址的話，舊版 App 裡的連結會失效。Google 的縮短網址可以換指向，
  但試算表連結不行——所以連結一旦公布就盡量不要換檔案。
